# v103：直接监督最终头部 UV 的重训

2026-09-07，延续 v103 分支。此前失败的 6000 步候选与审查记录保留；此次使用已发布 v102 的完整解析器作为冻结底座，新增独立学习分支修正最终头部 UV。

## 实质变化

`FinalHeadUVDecoder` 读取自动生成的 UV，以及原图正、背视图的 RGB、前景、头部语义和所属面概率。768 个头部 UV 格子通过立方体坐标和注意力交互，直接输出最终 alpha、颜色修改开关与颜色残差。推理不读取文件名、输入哈希、人工参考或训练掩码，也不强制所有胡子对称。

损失覆盖全部外层格子，包含透明负样本；错误新增和遗漏的格子加权。它同时监督最终颜色、跨面边界差异，以及在真值明确支持时才启用的胡子镜像和双层材质对应。它不再依赖真值像素到 UV 索引来代替最终输出监督。身体及无效 UV 区域在合并时原样保留。

## 数据范围

- 128 个训练源身份和 32 个隔离的验证源身份，各自生成语义明确的合成皮肤。先运行完整冻结解析器，缓存其真实错误输出及图像证据；训练中另加颜色变化、外层增删格子扰动。
- 已经明确修正的 `1ZW63H5Z8YNV57MT_edited.png` 作为 **1 条真实训练标注**。仅采用此前标注的胡子/头发范围，其余部分训练为保持底座结果。每 4 步在 batch 6 中加入一次，约占训练抽样的 1/24。
- 该人物之后只能用于检查训练拟合，不能再证明泛化。其余 16 个真实开发例不参与梯度；它们是反复使用的开发例，不是全新独立测试集。

## 验证一致性

训练与推理使用 FP32、固定数值设置和确定性算法。CUDA median 的索引实现不支持确定性，但背景估计只需要中位数值；在确定性模式下改用稳定排序取下中位数，保留 NaN 行为，并测试与旧实现数值一致。旧默认模式仍走原实现。

缓存生成与部署保持相同的参数标志和 no-grad 执行状态；底座不加入优化器，保存时直接继承父模型张量。

首轮在第 200 步因导出 PNG 一个绿色通道相差 1 而中断。复现显示：原图语义证据和进入 `refine_head_material` 前的 UV 完全一致，48 步颜色优化之后发生小幅浮点漂移；同进程重复运行最大差值为 0.00284，身体无差异。因而原先的完整 PNG 字节相等断言把底座颜色细化的漂移误作序列化错误。

修复后分开检查：① 序列化的 decoder 与内存模型使用同一缓存输入时逐值一致；② 完整推理中捕获 decoder 的实际输入，再交给内存模型，输出仍必须逐值一致；③ 缓存与完整链路的 alpha、身体、图像语义证据必须严格相等，两个 decoder 输出都必须保留各自输入的身体。仅头部 RGB 允许浮点最大差值不超过 1/255，且 PNG 最大通道差值不超过 1。每次输出 `roundtrip_步数.json`，如有差异明确记录 `rgba_exact: false`，不会声称字节相同。超过这些边界仍终止训练。

模型、优化器、步数/学习率状态、Python/NumPy/CPU/CUDA 随机状态在验证前写入同一个原子恢复文件 `training_state_latest.pt`。验证中的模型初始化不会消耗后续训练的随机序列。`--resume` 校验底座、缓存、batch 和总步数一致，然后恢复并重试验证；`--stop-after` 可在保持总步数学习率计划的情况下暂停。旧第 200 步没有优化器状态，因此首次恢复复用数据缓存，从第 0 步重跑；不伪称精确续训旧状态。

9 项单元测试覆盖透明格梯度、多余/缺失格惩罚、身体隔离、保存加载一致、条件镜像、背景中位数兼容、优化器与随机序列精确恢复、写入中断保留旧断点，以及数值容差不能放过 alpha/身体变化。另以完整 GPU 训练在第 200 步暂停并恢复，检查真实恢复链路。

## 运行和产物

```bash
bash dense_uv_parser/run_v103_final_uv_retraining.sh
```

运行根目录：`dense_uv_parser/runs/v103_final_uv_retrain_20260907/`。`cache/manifest.json` 记录生成进度、源身份和标注 provenance；原 `training/` 保留失败记录。修复后使用 `training_recovery_check/` 跑到第 200 步，再从其完整恢复状态接续到 `training_recovered/`。计划共 6000 步，第 200 步和每 1000 步保存模型、合成验证、训练样例拟合以及其余真实开发例的自动 UV/渲染。完成缓存不重新生成。

新 checkpoint 的底座 `model` 字典直接继承父文件；只有 `final_head_uv_state` 是新增训练权重。`infer.load_parser` 仅在 checkpoint 包含这个字段时启用新分支，`accessory_pipeline` 在原始补全和材质处理之后应用它。

训练完成不自动发布，不覆盖数据目录已有皮肤。是否有效需同时检查最终 UV、保留的真实开发例，以及训练身份隔离的验证集，不能仅凭这一个已进入训练的胡子样例判断。
