# 01 问题定义与背景

## 1.1 这个系统在解决什么问题

Dense UV Parser 的任务可以概括成一句话：

> 输入两张固定视角的 Minecraft 角色渲染图（正面、背面），输出一张
> 64×64 的 RGBA 皮肤图集（skin atlas / UV map），使该图集在相同相机
> 设置下渲染回去，能还原出输入的渲染图。

这是一个典型的**逆渲染（inverse rendering）**问题：

```text
正向： 皮肤图集(64×64)  ──► 渲染器 ──► 渲染图(256×512)
逆向： 渲染图(256×512)  ──► 解析器 ──► 皮肤图集(64×64)
```

正向过程（`SkingToolkit/renderer.py` 中的 `DifferentiableRenderer`）
是完全已知的：给定一张皮肤纹理和固定的相机/姿态/光照约定，用可微的
纹理采样（`F.grid_sample`）把图集映射到屏幕上。逆向过程则是本系统要
学习的：给定屏幕上每个像素的颜色，推断它来自图集上的哪一个纹素
（texel）、属于哪一层（内层/外层）、哪个身体部位、哪个面。

## 1.2 为什么这不是一个平凡的问题

从一张渲染图还原纹理，看起来只是"把像素抄回去"，但实际上有四个
本质困难：

**1. 像素是"分层"的，且层边界存在混合。** 皮肤图集上的 alpha 是
**二值**的——数据集把半透明像素直接置为全不透明
（`skin_dataset.py` 中 `(alpha > 0) & (alpha < 255)` 的像素被
置为 255），所以并不存在"半透明纹素"的麻烦。但渲染仍然是
"外层盖内层、内层盖背景"的合成：一块不透明外层纹素会把内层
**完全遮住**，此时该像素的颜色属于外层而不是你想恢复的纹素；
同时渲染器默认用**双线性采样**（`renderer.py` 的
`sampling_mode="bilinear"`），在内外层交界处会把二值 alpha
插值成 0~1 的**分数 alpha**，产生"外层颜色 + 内层颜色"按权重
混合的抗锯齿边缘像素（轮廓边缘还会混入背景色）。因此逆向过程
不能"直接取色"，而必须做分层路由 + 稳健的纹素投票。

**2. 遮挡与透明空洞（occlusion & transparent holes）。** 外层装饰
（如帽子）会挡住内层；反之，如果外层有一个透明洞（例如帽檐下露出
的脸），透过洞看到的是内层甚至背面。背对相机的那一面（backface）
永远看不到，只能靠对称性或修复来补。

**3. 信息丢失（ill-posed）。** 64×64 图集约 4096 个纹素，256×512
渲染图约 13 万像素，正向映射是多对一：大量像素映射到同一个纹素。
而且纹理细节（如眼睛、脸上的像素）在渲染后被重采样、被其他层覆盖，
几乎不可能逐像素精确还原。因此系统不需要"逐像素回归"，而是需要
**路由（routing）**：决定每个可见像素属于哪个图集纹素，再在多个
源像素之间投票选出颜色。

**4. 视角歧义（view ambiguity）。** 正面和背面渲染在很多皮肤上是
对称或相似的（例如纯色皮肤）。如果网络不知道"这张图是正面还是
背面"，同样的像素会对应不同的图集坐标。所以模型必须显式地以
**视图索引（view id）** 为条件。

## 1.3 系统的设计哲学

为了应对上述困难，系统采用了"**几何锚定 + 语义条件 + 确定性后处理**"
的三层结构：

1. **固定几何锚定（geometry-anchored）**：Minecraft 角色由固定
   cuboid（长方体）组成（头、躯干、双臂、双腿，每部分 6 个面），
   其 UV 布局是公开且固定的（见 02 章）。因此"屏幕像素 → 部位/面/
   UV 坐标"的候选关系可以由渲染器直接推导出来，**不需要网络去学**
   部位分割或 UV 回归。网络只负责在候选之间做**选择**，而不是
   **预测**坐标。

2. **语义条件（semantics-conditioned）**：路由（某个像素属于内层、
   外层还是更深处的次级表面）很大程度上依赖语义——"这是帽檐"
   "这是刘海""这是透明孔洞露出的脸"。系统用一个**冻结的 SigLIP2**
   视觉-语言模型提供空间特征和文本原型相似度（见 06 章），让路由头
   学会利用这些语义证据，而不是只看局部颜色。

3. **确定性后处理（deterministic repair）**：可见像素只能覆盖图集
   的一部分。看不到的纹素由一套**无学习、确定性**的拓扑修复算法补全
   （见 08 章）：先镜像，再按 3D 距离取最近邻，绝不凭空生成颜色、
   绝不跨部位复制、绝不动外层。这使得最终输出永远"可解释、可复现"。

系统的输出是一个 **10 通道内部条件张量（conditioning）**：

```text
[inner RGBA + evidence, outer RGBA + evidence]
```

即每个图集纹素记录：内层颜色/透明度/是否有证据，外层颜色/透明度/
是否有证据（带置信度时为 12 通道，每层多一个 confidence 通道）。
这个张量经过确定性修复后变成最终皮肤。

## 1.4 问题分解：系统要预测什么

对每个渲染像素，系统要预测（详见 04、05 章）：

- **前景/背景**（foreground/background）；
- **路由角色（route role）**：直接可映射的内层（inner）、直接可映射的
  外层（outer）、或次级/更深表面（secondary，例如透过透明外孔看到的
  背面或深处立方体面）；
- **精确的渲染器表面槽位（surface slot）**：包括复合表面与几何回退
  表面，用于把次级像素映射到正确的图集位置；
- **全局平移与均匀缩放**（可选 affine 头，默认推理关闭）；
- **该路由正确的概率**（置信度头，用于推理时的门控）；
- 图集层面的**外层可见性与占用**（可选头，用于外层的跨视角一致性与
  占用预测）。

而对"部位、面、UV 坐标"本身，系统**不预测**，而是从固定 cuboid
几何中直接查表得到——这是本项目与一般"端到端图像到图像"网络最
本质的区别，也是理解整个代码库的钥匙。

## 1.5 学习本系统能收获什么

- **计算机图形学**：UV 映射、纹理图集、alpha 合成、可微渲染、
  相机映射文件（mappings）。
- **深度学习**：多任务 CNN、以冻结视觉-语言模型为条件（FiLM、
  空间适配器、文本原型）、类别不平衡与 focal loss、置信度校准、
  多视角一致性损失、图神经网络（外层占用头）。
- **工程系统**：内存映射（mmap）特征缓存、checkpoint 原子写入与
  版本管理、可复现训练、面向生产的保守门控策略、确定性后处理。

## 本章要点

1. 任务 = 逆渲染：从固定视角渲染图恢复 64×64 皮肤图集。
2. 困难 = 分层与边界混合、遮挡、信息缺失、视角歧义。
3. 解法 = 固定几何提供坐标候选，语义特征辅助路由选择，确定性
   后处理补全缺失纹素。
4. 输出 = 10（或 12）通道分层条件张量，而非直接回归的图片。
