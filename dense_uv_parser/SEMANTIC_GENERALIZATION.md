# v61 semantic generalization fine tuning

The objective is to recover missed outer hair and hats using image context while
limiting new inner-to-outer mistakes. This experiment starts from
`runs/dense_uv_parser_v61/best.pt` and preserves its parameter shapes. It does not
use v94 weights or the paired manifest whose labels were generated by v94.

## Training changes

- Supervise each source pixel with the original skin alpha and exact renderer
  surface. Hair drawn on the base layer remains base-layer ground truth.
- Alternate canonical images with foreground-only appearance augmentation:
  foreground-normalized 3x3 blur, smooth lighting, modest contrast/tint and noise.
  No coordinate, alpha, silhouette or background changes are applied.
- Extract frozen SigLIP2 spatial/global features online from the actual input.
  Augmented images never use stale cached embeddings.
- During training, drop each of the two shallow decoder skip inputs for 10% of
  images. Evaluation and saved checkpoint architecture remain identical to v61.
- Freeze the coordinate route prior. Use 1e-5 initial LR for visual parameters,
  5e-5 for semantic adapters, and a cosine decay to 20%. AdamW state is fresh
  because this is a new fine-tuning objective, not an exact optimizer resume.
- Increase the outer false-negative loss from 0.75 to 1.25 and the outer class
  weight cap from 0.90 to 1.0. Add GT-labelled head-outer hard-positive mining
  (worst 20%, weight 0.15) and balanced flat-region route supervision (0.10).
- Keep the existing RGB/UV rendering losses on canonical batches. Appearance
  batches receive classification supervision, avoiding inconsistent RGB targets.

The unchanged CNN decoder and SigLIP2 adapters together predict each pixel's
inner/outer/secondary role. The fixed renderer still determines UV coordinates.
This experiment learns contextual routing; it does not add a hair/hat category
annotator or assume that everything resembling hair must be an outer layer.

## Data and evaluation

The original 180,000 sorted skin filenames are checked against the v61 semantic
cache metadata. Seed 1234 recreates the original 162,000/18,000 train/validation
split before any pilot subsampling. Selection and final-test indices are saved
in each run's config and are disjoint from training.

Validation reports clean pixels, a deterministic appearance stress test, and an
ablation that removes both semantic contributions. Head-outer recall is reported
separately. Hard UV metrics reuse v61 validation routing with the branch's current
33-source-pixel minimum; comparisons keep these settings fixed. This is not a
claim of exact parity with every launcher foreground/rescue option.

Checkpoint selection weights stressed head-outer recall 0.40, overall outer
recall 0.25, outer IoU 0.25 and inner IoU 0.10. Clean pixel and hard UV inner IoU,
outer IoU, outer precision and outer recall may each regress at most 1.5 percentage
points from the source checkpoint. Two consecutive failed guards stop training.
`best.pt` exists only after a score improvement that passes these guards.
`latest.pt` is diagnostic and is not automatically deployed.

An additional 256 skins are reserved for a final baseline/candidate comparison
after checkpoint selection. Synthetic stress results do not establish real-image
accuracy; real failures need visual review or independently verified labels.

## Run

From this checkout, use:

```bash
bash dense_uv_parser/run_semantic_generalization.sh \
  --output_dir dense_uv_parser/runs/dense_uv_parser_v100 \
  --epochs 2 --val_samples 512 --test_samples 256 --batch_size 8
```

The default source checkpoint is explicitly v61. `--train_samples 0` (default)
uses the entire original training split. `--train_samples 4096` creates a pilot.
Output directories must not already exist, preventing accidental overwrites.
Use a detached process/session for long runs.

Files in each run:

- `status.json`: PID, progress, completion or failure.
- `config.json`: provenance, settings, split indices, source checkpoint hash.
- `source/`: a copy of the code used by the full run.
- `baseline.json`, `metrics.jsonl`, `last_evaluation.json`: evaluation evidence.
- `latest.pt`, conditionally `best.pt`: standard v61-compatible checkpoints.
- `heldout_test.json`: final comparison on skins not used for selection.

To inspect a candidate with the current checkout's implementation:

```bash
python dense_uv_parser/run_local.py infer \
  --parser_checkpoint dense_uv_parser/runs/dense_uv_parser_v100/best.pt \
  --view_images test_imgs/front_rgba.png test_imgs/back_rgba.png \
  --output /path/to/a/new/output.png
```

`run_local.py` binds the historical `SkingToolkit` import name to this directory.
Without it, running files directly in `SkingToolkitDev` can import the sibling
`SkingToolkit` checkout. Existing production code and launcher defaults are
untouched. The v100 run uses standard numbered-run naming. Specify the checkpoint
explicitly when comparing it with v61.

Tests:

```bash
python dense_uv_parser/run_local.py test_semantic_generalization
```
